# Research Material and Validation

## Keyword material format

Create or update `Docs/关键词素材.md` or the project’s equivalent. Start with:

- Collection date;
- Project and keyword file;
- Source priority;
- Transcript limitations;
- Rules for excluding broken, suspicious or irrelevant links.

For every keyword use:

```markdown
### N. Keyword

User intent: one sentence describing the player task.

- Google: clean discovery URL and useful original results.
- YouTube: one or two relevant videos, with what each contributes.
- Official/Steam/Wiki: authoritative links.
- Verified facts: concise source-bound claims.
- Reusable page material: safe content and suggested structure.
- Status: evidence state and next recheck action.
```

End the file with a cross-validation matrix, pages ready to publish, pages needing evidence and a final recheck checklist.

## Research completion checks

- All research files are inside the project directory;
- `Docs/keywords.json` is valid JSON;
- The number of keyword sections matches the valid keyword count;
- Every final source is readable and not a dead or suspicious link;
- No competitor, fake SEO, third-party download or unverified source is included;
- Official facts are not attributed to player videos;
- YouTube notes do not pretend to be full transcripts;
- Dynamic claims have collection dates;
- Evidence gaps remain visible;
- Page matrix routes and keyword names agree;
- Older assignment conflicts are recorded rather than silently overwritten.

## Output package

Unless a smaller output is requested, hand off:

1. Page matrix with route, keyword, intent, cluster, priority, evidence and links;
2. Homepage brief in Markdown and, when useful, JSON;
3. Project-local keyword material file;
4. Icon prompt when requested;
5. Short completion, pending and pre-publication recheck summary.

## Limits

This workflow does not authorize bypassing access controls, downloading suspicious files, publishing unsupported claims, deploying a site, buying a domain or sending external messages.
